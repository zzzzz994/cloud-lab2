部署流程

从本地文件到公网可访问，只需三步；云平台屏蔽了底层服务器的全部运维细节。

01

创建仓库

在 GitHub 新建 Public 仓库 cloud-lab2，作为托管站点的源码容器。

02

上传页面

将 index.html 提交至仓库根目录，文件名必须为 index.html 作为默认入口。

03

开启 Pages

Settings → Pages → Source 选择「Deploy from a branch」，绑定 main 分支与根目录。

04

公网访问

等待约 1–2 分钟自动构建，即可通过 用户名.github.io/cloud-lab2 访问页面。

CORE CONCEPTS

核心技术要点

静态网站托管背后，是云厂商把存储、网络、证书、缓存封装成一个「点一下就能用」的服务。

🗄️

对象存储

网页文件以对象形式存放在云端存储中，按需读取、天然多副本冗余，无需关心磁盘与文件系统。

🌐

CDN 全球分发

内容自动缓存到边缘节点，用户就近取用，显著降低访问延迟并吸收突发流量。

🔒

自动 HTTPS

平台自动签发并续期 TLS 证书，无需手工申请、配置 Nginx，默认即具备加密传输能力。

⚡

弹性伸缩

访问量变化时由平台自动扩容，无需预估峰值、无需预先采购服务器硬件资源。

🔁

持续部署

每次 Git Commit 自动触发重新构建与发布，形成「提交即上线」的自动化交付链路。

💰

按量计费

免费额度内零成本，超出后按实际流量与存储付费，体现了云计算「按需使用」的核心商业模式。

COMPARISON

传统自建服务器 vs 云平台托管

同一件事，两种范式：前者买设备装系统，后者只需要提交代码。

✕ 传统自建

  • 需采购物理服务器或租用 VPS
  • 手动安装操作系统与 Web 服务器（Nginx / Apache）
  • 自行申请域名、备案、解析
  • 手动申请与续期 SSL 证书
  • 峰值流量需提前扩容，资源易闲置
  • 宕机、安全补丁均需自行运维

✓ 云平台托管

  • 无需服务器，提交代码即可发布
  • 运行环境由平台托管，零运维
  • 默认提供二级域名，可绑定自定义域名
  • HTTPS 证书自动签发与续期
  • 弹性伸缩，按实际用量付费
  • 自带高可用、冗余与 DDoS 防护
